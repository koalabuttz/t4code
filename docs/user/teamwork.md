# Project teamwork

Open **Teamwork** in a thread's header and choose **Use this thread** to make it the project's coordinator. On web and desktop, the command palette also offers **Open project teamwork**. Its conversation, model, and workspace stay available as the place to direct the team. Web, desktop, and mobile read the same board from the connected environment.

Create a **Swarm** when the outcome is clear and work can begin immediately. Create **Teamwork** when you want the coordinator to first refine a brief and milestones. Teamwork workers cannot start until you approve the brief. Promoting a Swarm to Teamwork keeps its tasks and history and adds this approval step.

The coordinator uses the team tools to create tasks, assign workers, and collect results. Roles name responsibilities and optionally select a provider and model; otherwise a worker inherits the coordinator's model. Workers use separate worktrees by default. T3 reports an unavailable model or failed worktree setup instead of silently choosing another.

Tasks have acceptance criteria, dependencies, and optional milestones. Include selected project knowledge in a worker's briefing. Open a worker to inspect its conversation and changes. A result needs evidence and review by someone other than its owner before it becomes done. You can approve a result or request changes yourself. Completing an initiative requires all remaining tasks to pass review and all milestones to be accepted. Completion does not merge or publish changes.

**Pause workers** stops assigned execution and cancels pending team notifications. **Resume** asks the coordinator to reconcile interrupted assignments and continue. **Cancel** retains the record; **Reopen** makes it active again. Reset a task to give it a fresh assignment. Reset dependent work before changing a prerequisite whose result it already uses. Changing the brief stops workers and requires fresh approval for Teamwork, or a resume for Swarm.

The board keeps decisions and questions together. A quiet update does not start an agent turn; **Notify coordinator** asks the coordinator to respond. Agents can address individual teammates. Failed deliveries stay visible with a retry action.

Project knowledge is explicit: retain a useful fact, correct it, or forget it. Forgetting removes it from current knowledge and future briefings; earlier messages and the correction history remain. Knowledge is context, not a replacement for project instructions. On web and desktop, **History** shows earlier board activity and changes.

Team state belongs to the project on its host environment. You can control it remotely from another client, but workers in one team currently run on that same environment. Provider support for delegated work and worktrees follows the normal T3 delegation capabilities.
